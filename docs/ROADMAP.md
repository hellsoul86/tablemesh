# Tokem 实施路线

v0 的状态和验证记录见各 issue；F01–F09 是后续工作。本文列出各项范围与验收条件，实际完成情况以对应记录为准。

## 1. 本轮 v0 目标

用两个独立账户完成真实德州牌局；让网页和 Agent 共用服务端合法动作；让运营在独立兑换网页导入演示预付卡库存，并让玩家用独立积分完成一次可核对兑换。首版可本地运行；尚未部署或公开上架，真实兑换默认关闭。

v0 接口见 PROTOCOL 与 ENGINE-CONTRACT。入座即准备，房主在至少两席有筹码时开局。独立准备、坐出和局中换席仍是后续功能，UI 不提供这些操作。

## 2. 本轮 v0 Issues

### [I01](https://github.com/hellsoul86/tablemesh/issues/1) — 建立可运行的工作区和产品基线

**范围**：工作区、核心/服务器/玩家网页/兑换网页/插件边界、共享 DTO、开发启动与验证脚本；把产品、设计、架构文档落到项目。确定环境变量模板，仅给示例值。

**依赖**：无。

**验收**：干净安装后按 README 可启动；所有包可构建/类型检查；玩家网页和兑换网页入口能区分；不把密钥、真实卡密或会话数据提交到公开仓库。

**证据**：安装、构建和类型检查的命令与退出码；实际启动地址；最终文件结构及 diff。

### [I02](https://github.com/hellsoul86/tablemesh/issues/2) — 统一账户与会话授权

**范围**：本地注册登录、会话、本人账户查询、退出和独立运营凭据。网页与插件调用都从服务端凭据取得身份。

**依赖**：I01。

**验收**：两个隔离会话对应不同账户；更改请求体 accountId 不会冒用他人；未认证请求返回结构化错误；普通账户不能导入库存；UI 明示开发身份。生产身份接入不算本项完成条件。

**证据**：身份隔离、未登录、伪造身份和运营越权测试；两个会话的非敏感账户 ID。

### [I03](https://github.com/hellsoul86/tablemesh/issues/3) — 房间、席位和开局生命周期

**范围**：列房、建房、加入、取得席位、快照；2–6 席德州配置；房主开始一手、结算后再次开始；原子席位分配。

**依赖**：I02、I04。

**验收**：两个账户能进入同房不同席；同账户不会占多席；满员、无效配置和未满足最小人数均被拒绝；入座即准备；只有房主能开始；进行中不能插入新参与者破坏牌局。UI 只提供已实现的退出/关闭能力。

**证据**：房间 API 测试与跨账户实际调用；满房并发测试；下一手开局结果。

### [I04](https://github.com/hellsoul86/tablemesh/issues/4) — 冻结可扩展游戏契约和隐私边界

**范围**：共享 DTO、规则模块接口、动作窗口、事件和本人视图。德州具体字段留在德州类型中；通用 ActionWindow 支持 eligibleSeats 集合及 single/parallel 模式。

**依赖**：I01。

**验收**：服务器、网页和插件消费同一协议；legalActions 自带可执行类型和额度限制；请求含 requestId、stateVersion、windowId；核心内部牌堆/私牌不能通过通用序列化泄漏；通用契约不要求永远只有一名行动者。

**证据**：协议文件、编译/类型检查、公开与私密视图序列化断言；说明哪些多方能力只是契约预留。

### [I05](https://github.com/hellsoul86/tablemesh/issues/5) — 实现可完成整手的德州规则引擎

**范围**：2–6 人、庄位/盲注、发牌和四轮下注、弃牌/过牌/跟注/加注及全下、牌型比较、主边池、拆分/退款、结算与下一手。

**依赖**：I04。

**验收**：确定性牌序可复现实例；禁止非法动作和额度；不足额全下、加注权、单人留存、全员全下自动发完公共牌、边池、平局及未跟注筹码退回都正确；每次结算筹码守恒；核心不做 IO、随机数和系统时间读取。

**证据**：规则测试命令与结果、关键场景输入和分配结果、尚未实现的规则。

### [I06](https://github.com/hellsoul86/tablemesh/issues/6) — 权威动作、同步、幂等与重连

**范围**：服务端动作验证、快照/事件、游标、版本冲突、请求幂等、截止时间、持久化与恢复。v0 使用轮询，SSE/WebSocket 留待后续。

**依赖**：I03、I05。

**验收**：同一 requestId 重放不再次扣筹码；同 key 不同 payload 被拒绝；旧 stateVersion 返回冲突与可恢复最新状态；请求必须属于当前账户席位和窗口；刷新/重连可继续；德州超时仅过牌或弃牌；持久化恢复不得泄漏完整引擎状态。

**证据**：幂等/并发/版本测试、实际断线恢复截图或视频、恢复前后版本与账户视图对照。进程重启恢复与浏览器刷新分别验证。

### [I07](https://github.com/hellsoul86/tablemesh/issues/7) — 提供账户、积分、房间与动作插件接口

**范围**：薄工具层，返回账户、积分、房间快照、本人 legalActions，允许授权的建房/入座/开局/动作；提供兑换网页链接。具体插件运行格式按可验证的目标宿主文档执行。

**依赖**：I02、I06、I08。

**验收**：Agent 可以用工具完成至少一串合法动作；工具不返回卡密、对方私牌或牌堆；插件和网页动作共用验证逻辑；有结构化错误与调用示例；说明仅完成本地工具运行还是实际宿主安装。公开上架不包含在本 issue 中。

**证据**：真实工具请求/响应（脱敏）、合法动作序列、卡密与隐私响应断言、安装/启动文档。

### [I08](https://github.com/hellsoul86/tablemesh/issues/8) — 独立平台积分账本

**范围**：整数余额、可用/冻结、账本、注册演示积分、兑换 reserve/capture 及业务幂等。游戏筹码不得直接调用积分结算。

**依赖**：I01、I02。

**验收**：余额不能为负；重复发放/消费只生效一次；并发消费不能超额；发放与消费可追溯；玩家不能自行调任意余额；牌局胜负不会改变积分，模型调用成本不会记为收入。

**证据**：账本一致性测试与并发测试；牌局前后积分不变记录；注册积分的唯一账本记录。

### [I09](https://github.com/hellsoul86/tablemesh/issues/9) — 独立兑换网页、库存导入和订单

**范围**：商品列表、兑换确认、订单、仅网页可见的卡密；运营导入演示预付卡；库存加密、重复校验；真实兑换默认关闭。

**依赖**：I02、I08。

**验收**：运营成功导入无价值演示卡；普通用户导入被拒；余额不足/缺货不扣分；重复请求只产生一个订单与一次扣分；两账户抢最后一卡只成功一个；已分配卡不再次出售；卡密只向订单所有者返回，插件无该工具；UI 清晰展示 pending/fulfilled/failed，不能伪造退款；真实卡启用开关在服务端检查。

**证据**：导入到兑换的实际网页操作与截图；并发、幂等、权限、库存和账本测试；加密库存、无明文卡密日志及缺少密钥时禁用的检查。

### [I10](https://github.com/hellsoul86/tablemesh/issues/10) — 实现中文大厅、牌桌和移动交互

**范围**：深色棋牌俱乐部风格、中文账户/大厅/牌桌/积分页面、真实房间数据、本人私牌、公共牌、席位、合法动作、下注输入、结算与连接状态。

**依赖**：I01、I04；最终集成依赖 I06、I08。

**验收**：桌面和 390px 均能从登录到完成一手；网页按钮与 legalActions 一致；加注写明“加注至”；非行动者明确展示等待；金额输入符合服务器范围；没有整页横向溢出；可用键盘完成主要动作；空房、错误和重连状态有实测覆盖。尚未实现的聊天、观战、准备、坐出不得出现可点击假按钮。

**证据**：两个隔离浏览器身份的操作和截图，桌面/移动实际尺寸，build/typecheck 结果，状态覆盖记录。

### [I11](https://github.com/hellsoul86/tablemesh/issues/11) — 首版集成验收、公开文档与完成状态核对

**范围**：联机牌局、工具、积分、兑换跨模块流程；启动说明、配置示例、已知限制、后续 issues；按用户授权创建并更新公开仓库和 issues。

**依赖**：I01–I10。

**验收**：从干净启动状态至少两个独立账户完成一手，并再次开局；Agent 使用同一动作协议操作；测试卡从导入到唯一兑换成功；集成版本通过 check、plugin:check 和浏览器测试；文档区分已实现/未实现/未部署/未上架；未完成 issue 保持开放。

**证据**：最终源码修订、验证命令与退出码、网页截图/运行记录、问题链接、剩余缺口。通过本地测试不替代 CI、生产部署或上架证据。

### [I12](https://github.com/hellsoul86/tablemesh/issues/21) — 锁定参赛席位与主动离席处罚

**范围**：固定参赛账户/席位、显式主动放弃确认、持久信誉和冷却、立即/下一窗口弃牌、全下权益保留、结算后移除；网络断连不罚，积分不罚。

**依赖**：I02、I03、I05、I06、I07、I10；I11最终集成包含本项。

**验收**：开局不能换人；无确认拒绝；同账户/房间/局只罚一次且重启不重复；首次信誉-10与5分钟冷却，24小时重复-20与15分钟，信誉最低0；冷却禁止新建/入座/新局开始；已有牌局动作和重连继续；全下合法权益保留；结算后离场且同房筹码不重置。

**证据**：API、持久化、并发/幂等及全下测试，网页确认和待离场状态，真实SDK调用，集成版本的最终测试。处罚数值是 Tokem 的 v0 策略。

## 4. 当前未决问题

1. 生产身份提供方和插件分发目标；首版可在开发账户与本地工具层完成工程验证。
2. 平台积分真实来源、是否售卖、兑换比例、对局是否产生积分；先用免费筹码与开发积分，保留独立账本。
3. token 卡供应商、可分发范围、有效期与售后条件；首版支持导入演示库存，无需猜测供应商 API。
4. 公开目录对玩法、积分、兑换及经济活动的要求；需要按目标目录规则核验，网页拆分不构成豁免。
5. 首发目标部署环境和持久化/备份约束；本地启动不等于部署完成。

这些事项影响生产能力和分发；本地 v0 使用免费筹码、演示积分和测试库存。
