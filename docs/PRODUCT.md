# Tokem 产品说明

Tokem 提供中文联机牌桌。首款游戏是 2–6 人无限注德州扑克，玩家可以用网页操作，也可以把同一账户的游戏令牌交给 Codex 插件。两种入口使用相同的房间、席位和规则，不按操作者是真人还是程序区分权限。

当前版本可在本地完成牌局和演示兑换，尚未部署或公开上架。本文区分已实现功能与后续计划；各项验收记录见 [实施路线](ROADMAP.md)中的 issue。

## 1. 当前可用范围

| 入口 | 已实现 | 后续计划 |
| --- | --- | --- |
| 账户 | 昵称与密码注册、登录、退出、游戏令牌创建/列表/撤销 | 正式身份提供方、按房间和时限授权 |
| 大厅 | 公开房间列表、创建房间、用公开房间码进入 | 私密邀请、搜索、房间过期与关闭 |
| 牌桌 | 2–6 人德州、入座、房主开局、合法动作、结算、再开一手 | 独立准备、坐出、换席、房主转移、聊天 |
| 联机 | 服务端校验动作、轮询更新、超时、刷新重连、持久恢复 | SSE/WebSocket、大规模运行 |
| 积分 | 可用与冻结余额、明细、注册演示积分、兑换扣除 | 正式积分来源、定价、退款和奖励政策 |
| 兑换网页 | 商品、确认兑换、订单、本人查看卡密、演示库存导入 | CSV 预览、批次管理、真实商品和售后 |
| Codex 插件 | 账户、积分、房间与游戏动作工具、本地 SDK 调用 | 完成实际宿主调用验证、公开分发核验 |

## 2. 账户和授权

网页使用 HttpOnly 会话。牌桌和兑换网页在同一 hostname 下共享登录，端口不同不影响会话。服务端从会话或游戏令牌识别账户，不接受客户端自行指定操作者身份。

账户页可创建带用途备注的游戏令牌，创建时仅展示一次，之后只列出备注和到期时间。用户可以撤销令牌；退出网页不等于撤销已签发令牌。游戏令牌允许账户、积分和牌桌操作，不能导入库存、查看订单卡密或代替运营令牌。

运营令牌独立配置。运营页面用密码输入框接收，仅保留在当前页面内存中；关闭页面后需要重新输入。卡密仅在独立兑换网页由订单所有者明确点击后显示，不放入插件响应、网址或浏览器持久存储。

## 3. 筹码、积分和信誉

这三个数值分别记录：

| 数值 | 用途 | 当前变化方式 |
| --- | --- | --- |
| 练习筹码 | 本房间下注和结算 | 入座初始分配，按德州规则输赢；同房离席重入不重置 |
| 平台积分 | 独立网页兑换 | 注册默认赠送 1000 演示积分，数额由服务配置；兑换预留并扣除 |
| 牌桌信誉 | 记录主动放弃牌局 | 初始 100，确认主动放弃后扣减，最低 0 |

牌局输赢不改变平台积分。积分不能购买，筹码不能兑换积分；没有对局积分奖池。玩家自己的模型调用成本不会自动计为平台收入或奖池出资。真实积分发行、奖励和兑换比例未决定，见 [F04](https://github.com/hellsoul86/tablemesh/issues/15) 与 [F09](https://github.com/hellsoul86/tablemesh/issues/20)。

余额分为“可用积分”和“冻结积分”。兑换操作保留唯一请求编号；重试同一请求不会生成第二份订单或再次扣分。缺货和余额不足不完成扣款，网页不能把未知结果显示成成功。

## 4. 一张房间的流程

1. 创建公开房间，设置名称、2–6 个席位、初始筹码、盲注和行动时间。创建者成为房主，进入房间后点击入座。
2. 其他账户从大厅或公开房间码进入，在空席上入座。同一账户不能占两个席位。
3. 入座即准备。至少两位有筹码的玩家就座后，由房主开始一手；若参与者处于离席冷却期，不能开始新手。
4. 开局后锁定本手参赛账户和席位，不允许中途换人或插入新参与者。未入座者不能加入当前一手。
5. 玩家按服务端提供的动作和金额范围操作。非行动者显示等待对象；私牌只给所属账户，其他人看不到牌堆或未公开的手牌。
6. 超时可过牌则过牌，否则弃牌。刷新和断线不会重置倒计时，恢复连接后取得本人当前牌局。
7. 结算显示主池、边池、获胜者和未跟注退款；公开结算记录保留当时的账户身份，换席后不把上一手奖励记到新玩家名下。
8. 房主可再开一手。待离席者在结算后移除；筹码不足两席时不能开局。补充筹码、转移房主和关闭房间暂未实现。

返回大厅只是页面导航，不会调用离席。局间可以离开席位；进行中的主动放弃按下一节处理。

## 5. 主动放弃与网络断开

德州每手算一局。用户点击“主动放弃本局”后，先看到后果说明，可以取消。确认后，在当前或下一次轮到该玩家时自动弃牌；已全下的投入和结算权益保留。席位显示“已放弃 · 结算后离席”，在终局前不能由别人接替。

| 情况 | 信誉扣除 | 新局冷却 |
| --- | --- | --- |
| 首次主动放弃，或此前 24 小时内没有主动放弃 | 10 | 5 分钟 |
| 24 小时内重复主动放弃 | 20 | 15 分钟 |
| 刷新、断线、关闭网页、返回大厅 | 0 | 无 |

冷却期间不能创建房间、加入新桌或开始新手；其他已经进行中的牌局仍可操作。不扣平台积分。同一账户在同一房间同一手只处罚一次，重复请求和服务重启不重复处罚。截止时间已经到达的旧确认请求先按普通超时处理，再返回版本冲突；不会把过期的确认算作主动放弃。

数值是 Tokem 的自定规则。交互参考 [PokerStars Seat-Me](https://www.pokerstars.com/help/articles/seat-me-introduction/) 的离席确认与重复冷却，以及 [Board Game Arena FAQ](https://en.boardgamearena.com/faq) 的信誉机制；不声称这些平台采用相同数值。实现记录见 [I12](https://github.com/hellsoul86/tablemesh/issues/21)。

## 6. 德州和其他棋牌

当前德州包括庄位与盲注、四轮下注、弃牌/过牌/跟注/加注、全下、主边池、平局拆分、未跟注退款和下一手。加注金额表示本轮累计投入。短额全下是否重开加注权由规则引擎判断，网页和插件只展示当下允许的动作。

游戏规则与账户、房间、积分分离。通用动作窗口支持一个或多个有权响应的席位，并携带截止时间；不能把所有棋牌都固定成永远只有一人行动。多人响应目前是接口预留，不代表麻将抢杠胡或拖拉机抢主已经可用。

后续先明确具体规则版本，再实现和测试：

- [拖拉机](https://github.com/hellsoul86/tablemesh/issues/17)：搭档、主牌、抢主、甩牌、升级及四人完整对局。
- [麻将](https://github.com/hellsoul86/tablemesh/issues/18)：选定地方规则，处理吃碰杠胡、响应优先级、多家和牌及私密信息。

## 7. 独立兑换网页

用户先看商品所需积分和可用库存，再进入确认页核对本次消耗与兑换后余额。确认成功后进入订单，卡密默认隐藏；订单所有者可显示、复制和再次隐藏。重新打开页面仍默认隐藏。订单列表和积分明细用于核对交易。

运营人员在“库存管理”输入商品 ID、名称、每张积分和逐行卡密，提交整批演示库存。空行会忽略，重复输入会被拒绝。成功后表单清除卡密，只显示导入数量。当前不支持 CSV 文件上传、预览或批次编辑。

库存以加密形式保存，每张卡只能分配一次，积分和库存一起提交，防止两人同时兑换最后一张卡。缺少库存密钥时关闭相关操作，不降级为明文。无需假定某个供应商提供 API；首版只使用运营预先导入的无实际价值演示卡。

真实兑换默认关闭。商品来源、有效期、授权范围、退款、税务和售后没有确定之前，演示流程不能当作真实服务承诺。把兑换放在网页上是产品分工，不是绕过公开插件目录要求的办法。

## 8. 运营、记录与后续发布

当前保留账户、积分流水、房间动作、结算和离席处罚记录，用于排查重复操作和恢复牌局。公开事件不包含未摊牌私牌；结算记录绑定当时的参与者身份。

尚未实现自动反串通系统。后续应按异常行为检查关联对局、协作输送和重复获利，由人工复核并允许申诉，不以真人或程序身份直接判定作弊。记录留存和隐私政策需与正式运营一起确定，见 [F08](https://github.com/hellsoul86/tablemesh/issues/19)。

尚未接入生产指标采集。上线前应记录注册到入座转化、成功开局与完整结算比例、重连成功率、动作失败原因、超时率、主动离席率、兑换失败原因和库存余额；不采集卡密或令牌。先用这些指标判断可用性，再考虑奖励活动。

本地 SDK 和插件启动入口已验证，实际 Codex 宿主调用仍未完成，两次 CLI 尝试遇到模型请求超时。`${PLUGIN_ROOT}` 的 MCP 参数展开也未确认，现有说明提供显式路径配置。生产身份、部署备份恢复、公开分发、真实经济功能分别对应 [F01–F05](ROADMAP.md)，本地测试通过不代表这些事项完成。

## 9. 自选模型与席位托管

用户可为自己的账户保存一份模型配置：服务协议、明确包含 API 前缀的地址、模型 ID、密钥和调用限制。支持 OpenAI 兼容 Chat Completions 与 Anthropic Messages；本机 OpenAI 兼容服务允许无密钥。远程服务需要 HTTPS 和密钥。密钥由服务端加密保存，网页只得到是否已保存，不得到原值。

OpenAI 兼容协议可明确选择输出上限字段 `max_tokens` 或 `max_completion_tokens`，默认前者；Anthropic 固定使用 `max_tokens`。接口不会猜测服务类型、补地址路径或因参数错误自动重试。

连接测试使用已保存配置发送一次小请求，不含牌局。测试有唯一请求编号，丢失响应后查询原编号不产生第二次模型调用。保存或删除配置会暂停该账户已开启的托管。配置只能通过网页会话写入；游戏令牌不能改密钥或发起连接测试。

托管控制的是已入座账户的当前席位，不能代建房、入座或开局。开启后持续本桌，直到用户接管、错误、预算耗尽、授权失效或席位离开；新一手仍需房主手动开始。直接手动操作会先暂停托管，即使该动作因旧牌局版本未被接受，旧模型回复也不能继续提交。

只在本人有合法动作时请求模型，同席最多一个请求在途。输入包含本人手牌、公开牌局和合法动作，不含其他私牌、牌堆、昵称、账户编号、令牌或卡密。模型输出必须通过原有游戏规则和版本校验，不能自行决定身份或扩大下注范围。超时、非法结果、旧回复均暂停托管，不自动重试；牌桌普通超时规则照常生效。

默认限制为单次 5 秒、输出 256 token、每手 20 次、每次开启 100 次。调用前计数，失败也占次数；同一次服务运行中暂停后重新开启，不会清除同手计数。服务重启会重置计数并关闭托管，需要手动开启。每次开启的计数可重新开始，但已经开启时重复点击不重置。限制仅约束次数和输出长度，不保证供应商账单金额。

网页刷新或断开不会自动停止已授权的托管，恢复时查询服务端状态。服务端重启后不恢复模型调用，用户需再次开启。接管不会离席、换人或扣信誉，模型费用也不改变平台积分或筹码。

本地自动化验收使用无外部费用的假 HTTP 服务。真实供应商的可用模型、收费和密钥由用户自己选择，不能把本地测试写成真实供应商调用成功。
