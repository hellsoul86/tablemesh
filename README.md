# Tokem

Tokem 是一个中文联机棋牌项目。目前可以玩 2–6 人无限注德州扑克：创建房间、邀请朋友入座，完成一手后继续开局。网页版与 Codex 插件使用同一个账户和房间，也可让你自己的 agent 通过 MCP 使用这些操作。模型和算力由你自己的客户端提供，平台不接收模型服务密钥。

商城在独立网页中。当前只提供演示积分和演示卡兑换，不提供实际算力；牌桌筹码与平台积分分开，牌局输赢不改变积分。

## 本地开始

需要 Node >=22.13 和 npm。CI 使用 Node 22/24。

```bash
npm ci
npm run dev
```

打开 [牌桌大厅](http://127.0.0.1:5173/app/lobby)。用两个独立浏览器会话分别注册账户，例如普通窗口和无痕窗口：

1. 创建房间，设置席位、筹码和盲注，然后点击入座。
2. 把房间码交给另一位玩家，对方打开房间并入座。
3. 至少两位有筹码的玩家入座后，由房主开局。入座即准备。
4. 轮到自己时选择弃牌、过牌、跟注或加注。“加注至”是本轮累计投入，包含已经下注的筹码。

[积分兑换](http://127.0.0.1:5174/shop) 与牌桌共用登录。两站都使用 `127.0.0.1`，不要混用 `localhost`，否则浏览器不会共享会话。API 监听 `http://127.0.0.1:4100`。

开发启动器先构建核心包，再启动三个服务。网页改动会自动更新，服务端改动后需要重启。Codex 插件的本地配置见 [插件使用说明](plugins/tablemesh/README.md)。

## 连接你自己的 agent

1. 在网页“账户”中创建游戏令牌，保存到运行客户端的环境变量 `TABLEMESH_TOKEN`。令牌只在创建时展示一次；它允许当前账户的游戏操作，不能访问兑换卡密。
2. 在“连接你的 agent”中复制 HTTP MCP 配置，添加到客户端配置中。配置模板只引用环境变量，不包含令牌。使用本机 stdio 时，切换接入方式并填写仓库绝对路径；详细启动方式见 [插件说明](plugins/tablemesh/README.md)。
3. 重新连接客户端，让它读取 Tokem 账户以确认授权。打开房间并复制“给 agent 的房间提示”，交给客户端。客户端先入座，房主再开局。

本机默认 HTTP 地址是 `http://127.0.0.1:4100/mcp`。这里的 `127.0.0.1` 指客户端运行的机器；云端或另一台电脑上的客户端需要实际可达的 HTTPS 地址。项目没有已经上线的公共服务，运营者应在部署时提供可信的 MCP 地址。

例如 Codex 的 HTTP 配置（令牌仍由环境变量提供）：

```toml
[mcp_servers.tablemesh]
url = "http://127.0.0.1:4100/mcp"
bearer_token_env_var = "TABLEMESH_TOKEN"
tool_timeout_sec = 45
```

agent 在自己的客户端读取本人牌局、等待行动窗口、选择合法动作，再提交。等待工具每次最多等待 25 秒，返回后由客户端继续执行。房间提示默认只参与一手，不自动开下一手或主动离席。用户可继续手动玩；网页动作不会停止外部客户端。想转为手动操作，应在客户端停止 agent，或撤销其游戏令牌，阻止后续调用。关闭网页、断开 MCP 或取消等待不算离席，行动时限仍然有效。

接入失败先检查地址可达性和令牌有效期。状态已过期时重新读取牌局再决定；某次提交结果不确定时，以原请求编号重试同一动作，避免重复提交。复制配置本身不代表客户端已连通。

## 已实现的功能

- 注册、登录、退出，查看积分明细，创建和撤销游戏令牌。
- 公开房间、2–6 人德州、主池与边池、全下、结算和再开一手。
- 刷新与断线重连；超时可过牌则过牌，否则弃牌。
- 独立兑换网页：商品、确认兑换、订单和本人卡密查看；运营可导入演示卡库存。
- HTTP MCP 与本机 stdio 接入，11 个工具涵盖账户、积分、房间、动作及等待轮到自己。客户端与网页使用相同席位权限，工具不返回卡密或其他玩家的私牌。

拖拉机、麻将、私密邀请、房主转移、聊天、正式身份和生产部署仍在[后续计划](docs/ROADMAP.md)中。

## 演示兑换配置

注册默认获得 1000 演示积分，数额可通过服务配置调整。积分不能购买，练习牌局也不会赚取或扣除积分。玩家支付给模型服务商的费用不会成为平台收入或奖池。

要试用库存导入和兑换，复制 `.env.example` 为本地 `.env`，按注释配置随机 32 字节 base64 库存加密密钥和独立运营令牌，然后重启服务。在兑换网页的“库存管理”中输入运营令牌，按行导入演示卡密。普通账户没有导入权限；缺少加密密钥时，导入和卡密查看均不可用。

真实兑换默认关闭。现有库存不依赖供应商 API，真实商品来源、授权、定价与售后尚待确定。不要把真实卡密、令牌、数据库或密钥提交到仓库。

## 离席与重连

一手开始后，参赛账户和席位锁定到结算。刷新、断线、关闭网页或返回大厅不会主动离席，也不扣信誉；行动倒计时仍会继续。

主动放弃本局需要确认。非全下玩家在轮到自己时自动弃牌，全下玩家保留结算权益，席位在本手结束后移除。信誉初始为 100：首次主动离席减 10，冷却 5 分钟；24 小时内再次主动离席减 20，冷却 15 分钟，信誉最低为 0。冷却期间不能创建、加入房间或开始新手，已有牌局仍可继续，平台积分不受影响。

这些数值是 Tokem 的自定规则。确认离席与递增冷却参考 [PokerStars Seat-Me](https://www.pokerstars.com/help/articles/seat-me-introduction/)，信誉机制参考 [Board Game Arena FAQ](https://en.boardgamearena.com/faq)。详细验收见 [离席规则 issue](https://github.com/hellsoul86/tablemesh/issues/21)。

## 测试与当前限制

```bash
npm run check
npm run plugin:check
npx playwright install chromium
npm run test:e2e
```

`check` 包含类型检查、规则与服务端测试和构建。浏览器测试使用独立账户，覆盖联机牌局、重连、结算、积分兑换及主动离席；接入流程另以两个独立 HTTP MCP 协议客户端和一个网页席位完成同一手，检查等待、并发旧版本、令牌撤销与本人视图。这是协议互通验证，不是对真实模型策略的评价。测试记录见 [Issues](https://github.com/hellsoul86/tablemesh/issues)，远端运行结果见 [GitHub Actions](https://github.com/hellsoul86/tablemesh/actions)。

HTTP MCP 已在真实 Codex 宿主中完成 11 个工具的发现，以及账户、大厅、本人牌局、等待与合法动作查询。该验证使用临时运行配置，没有启动模型决策回合；自主模型策略、持续后台运行、便携插件安装和 `${PLUGIN_ROOT}` 参数展开仍未验证。[插件说明](plugins/tablemesh/README.md)提供显式路径配置。

真实兑换、生产部署和公开插件分发尚未完成。把商城放在独立网页并不豁免插件目录对经济活动的要求，分发规则仍需单独核验。
